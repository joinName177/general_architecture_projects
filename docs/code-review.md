# Code Review 清单

本清单帮助 PR 作者自查、帮助审查者收集证据。唯一强制的 Git、PR、Review 与合并规则仍以 `CONTRIBUTING.md` 为准。

## 作者自查

- PR 只解决一个可审查目标，描述中写明目标、范围和非目标。
- 变更符合 `ARCHITECTURE.md`：不跨越模块边界、不引入循环依赖、不在 Presentation 直接执行外部 I/O。
- 行为变更具备可在旧实现失败的自动化测试；错误、权限、取消、资源释放和边界路径得到覆盖。
- 新增名称符合 `engineering-standards.md`；业务规则、用户文本、路由、错误码和配置没有散落硬编码。
- 对安全、隐私、复杂契约、算法、性能取舍和临时兼容方案写明原因或链接 ADR。
- 执行了适用的 `format:check`、`typecheck`、`lint`、测试、构建和 `verify`，并在 PR 中附结果。

## 审查者检查

- 先核对目标和非目标，再核对 diff 是否只包含必要变更；拒绝顺带重构、死代码或未使用依赖。
- 从不可信边界向内检查：输入是否验证、错误是否安全、取消/超时/资源释放是否完整、日志是否泄露数据。
- 从公开契约向内检查：模块 import 是否仅走 `public.ts`，状态所有权是否唯一，新的 API/Schema/配置是否有唯一 owner。
- 检查可读性：职责是否可用一句话说明，名称是否表达意图，分支是否可读，注释是否解释原因而非复述代码。
- 核对测试是否验证行为而非私有实现；确认修复缺陷的测试能在旧实现上失败。
- 涉及架构、身份、Capability、数据分类、外部契约、供应链或发布时，确认对应 owner 已审查。

## 审查结论

仅在 Required Checks 全部通过、讨论已解决、没有未完成占位项、所需 owner 批准有效时批准或合并。发现阻断项时，评论必须说明受影响的行为、风险和可验证的修正方向。
